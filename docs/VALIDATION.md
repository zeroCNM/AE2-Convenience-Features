# AE2 Convenience Features 0.11：空格填满背包与自检

## 0.11 本轮变更

在 NEI 物品栏、历史栏、书签和配方内，按住空格单击左键，将 AE 内该物品填入背包与快捷栏的可用容量。补满相同 meta/NBT 的未满堆叠后填空位，不替换其他物品、不占用盔甲或额外槽位。一键发送一次请求，按住不连发；空格+Shift+左键优先执行填满。

开始时无可提取库存且有样板才进入原生下单。已有库存不足以填满时只取实际库存，不补单；电量不足也只交付 AE 实际提取数量。满背包不提取。有库存时只调用一次原生耗电提取，按合法堆叠放置；若提取期间槽位改变，余量退回 AE，拒绝退回时仅掉落实有余量。

复用原有服务端主线程、终端校验与权限链、100 ms 限流及无线操作包。新增动作 3（客户端不提供数量），原动作/包编号不变。现有 NEI 接管点同时跟踪该次左键的按下、拖动与松开，避免向默认处理继续分发；非 NEI 物品、无终端或未满足快捷键时不接管。无新增运行前置、Mixin 目标、渲染查询或 tick 扫描。

未运行图形客户端。输入接管、配方页与其他模组共存，以及真实 AE 取物/下单均需用户实测，不能用下列自动回归代替。

## 0.10 保留的显示样式

NEI 配方查看页内物品库存数字为左下角绿色（0x7EFFB3），沿用书签样式及底部位置。白色可合成加号、零库存隐藏、机器列表排除及其他区域样式保留，位置与颜色需用户实测。

## 保留的已有行为

用户确认以“AE 实际制作完成”为触发点。正式包为 `AE2 Convenience Features 0.11.jar`；下次更新为 0.12，同轮重复构建不增版。

- 玩家订单实际完成后，在玩家打开的同一 AE 网络存储终端顶部增加临时整行。最新完成的物品在首格，旧的依次后移；按终端实际列数补空格，超过一行自动续行，使用终端原有滚动区域。
- 未打开终端时等待玩家下一次打开同网络终端；显示后服务器队列消费一次。不同玩家、不同 AE 网络隔离。成功合并进 CPU 的玩家订单分别记录，取消和失败订单不计入。
- 正常关闭终端后清除；一直打开则自首次显示起 60 秒整栏清除，后续完成不延长这一批的期限。过期后新完成的订单可以开始新一批。切换数量、确认和 CPU 状态子页面视为同次终端访问，期限继续计时。
- 使用原生终端库存引用、数量同步和虚拟格点击，不移动真实库存、不创建取物网络包。普通列表中的相同物品移到临时行，其他物品保持原排序；按完整 meta/NBT 区分。临时栏独立于普通搜索，数量仍是当前库存。
- 原生固定栏保留，显示在可见的临时行之后；滚动离开临时行后回到原位置。原生固定物品可以仍出现在固定栏，未修改其持久化配置。
- 不要求身上有无线终端；支持 AE2 原生存储终端和兼容子类（包括相应无线终端）。`completedCraftRows` 可以关闭本功能。

最多保存每名玩家最近 256 种待显示物品，满后丢弃最旧记录。服务器重启清除待显示的临时记录；AE 原生持久化订单继续制作，CPU 完成时可用原生保存的来源玩家与目标物品兜底。非物品输出（如原生流体类型）未加入本次临时物品栏。

## 新接口核实

已直接检查编译 AE2 977 与运行 AE2 1095 的实际 JAR 字节码，未依靠猜测签名：

| 接口 | 已核实结论 |
|---|---|
| 成功订单归属 | `CraftingCPUCluster.submitJob(IGrid,ICraftingJob,BaseActionSource,ICraftingRequester): ICraftingLink` 和 `mergeJob` 同签名；RETURN 非空才记录。来源使用 `PlayerSource.player`，目标使用 `ICraftingJob.getOutput`。 |
| 合并与取消边界 | 原生 submitJob 可内部调用 mergeJob，因此成功返回只追加归属，不清除之前玩家；实际完成、cancel()V 和 resetFinalOutput()V 清理归属。两版均已核实取消方法签名。 |
| 实际完成 | `completeJob()V` 的 `List.forEach(Consumer)` 调用前观察；此处已通过剩余任务检查，原生完成标志尚未置位。不取消、不覆盖原生方法，不往 CPU 的序列化监听器列表加入闭包。 |
| 完成判定细节 | 原生独立玩家订单的 CraftingLink 没有可靠的 done 轮询状态；最后任务完成后 `isBusy()` 已是 false。因此使用原生 `isComplete` 字段排除重复完成，而非轮询链接或检查 isBusy。 |
| 恢复任务 | 原生 `getSourcePlayer/getFinalMultiOutput/getGrid` 均存在；同一已跟踪 CPU 的合并订单保留各玩家目标，旧任务恢复可按 AE 保存的最后来源玩家兜底。 |
| 同网络终端 | `ContainerMEMonitorable.getNetworkNode` 及 `getTarget`；无线 host 是 portable host，node 可为 null，使用 `WirelessTerminalGuiObject.getGrid`。绑定与通知带当前 windowId、维度、网格标识和递增序号。 |
| 展示缓存 | 两版 `ItemRepo.view/list/sortSrc/rowSize/updateView` 签名一致。只改变 view，库存与持久固定栏不写入。每次 native updateView 之前恢复原视图，避免 null 空位进入原生 Shift 暂停分支。 |
| 原生格子 | 两版 `GuiMEMonitorable.pinSlots/monitorableSlots/perRow/setScrollBar` 和 VirtualMESlot 的坐标访问器均存在。近期行位于固定栏上方，沿用原生格子的鼠标命中。 |
| 版本差异 | GuiMEMonitorable.repo 字段在 977 为 IDisplayRepo、1095 为 ItemRepo；没有为该字段增加不兼容的访问器。通过 ItemRepo 的共同 sortSrc 关联终端。 |
| 混淆映射 | initGui、drawScreen 生成 SRG refmap；其余 AE 类和方法不混淆。没有新增第三方运行前置。 |

## 0.9 整体开销复核与优化记录

用户再次测试后打开终端恢复正常，卡顿点尚未稳定复现。0.9 未采集客户端帧耗时或对应时刻的服务器剖析数据，不能将偶发卡顿确定归因于本模组，也不能保证已经解决该现象。下面的优化针对可直接确认的重复工作。

| 路径 | 发现和处理 | 兼容边界 |
|---|---|---|
| 完成栏刷新 | 0.8 的本地 refresh 主动调用一次原生 updateView，可能重新筛选排序整个网络。0.9 只恢复/调整已由原生生成的 view；空首次绑定也不刷新；恰好到期时仍刷新以移除临时栏。编译字节码确认每次本地 refresh 的原生 updateView 调用由 1 次降为 0 次。 | 原生库存/搜索/排序的更新入口没有取消、节流或覆盖。继续在 native updateView 前恢复非空位的完整原视图，兼容 Shift 暂停。 |
| 显示快照 | 复用原视图快照容器，完成顺序在内容不变时复用不可修改快照。 | 仍保留完整原视图备份，避免为了省拷贝改写原生暂停/固定栏逻辑。数量引用仍为原生库存对象。 |
| GUI 帧路径 | 无临时行且无遗留偏移时跳过槽位扫描；目标偏移未变时不再 setY 或写 map。 | 不缓存整个布局，不跳过其他模组可能修改坐标后的观察。原生格子、点击和 GL 状态保护保留。 |
| NEI 图标与收集 | 相同 ItemStack 复用完整身份快照，每次仍比较物品/meta/完整 NBT。首次深拷贝后 5000 次重复查询没有额外根 NBT 深拷贝；嵌套数据变动会重新复制。缓存最多 4096 项、弱 key，关闭界面清理。 | 不按物品注册名或 NBT 对象地址代替内容比较，不降低权限/新鲜度检查。不跨其他模组绘制范围批量改动 OpenGL 状态。 |
| 无界面客户端 tick | 没有 NEI 界面、也没有待处理世界取物时，跳过终端背包扫描。 | 实际输入和 ACK 回退仍重新检查终端；不缓存操作权限。 |
| 完成通知服务端 tick | 没有新增完成物品且绑定未变时，不分配空数据包；没有待展示记录时避免玩家名规范化。 | canInteractWith 和同网络检查继续执行，没有改批次大小或通知延迟。 |
| 其他网络/取物路径 | 检查了缓存候选、监听器、请求队列、提取和下单路径，现有边界/批量/TTL 保留。 | 不更改服务器验证链、输入事件优先级、包编号、原生合成完成 Mixin、库存同步频率或 NEI 500 ms 有效期。 |

新代码未增加原生 API 或 Mixin 目标。已核实实际 Minecraft ItemStack 没有覆盖 equals/hashCode，适合对象弱 key；缓存 value 不保留 ItemStack，避免反向强引用。完整 NBT 比较仍可能有成本，因此只声称减少重复复制和额外整表重建，不声称测得游戏 FPS/打开耗时提升。

新增回归覆盖同一快照复用、快照不可变、局部重复刷新、搜索改变后恢复、空位清除、10 万条目引用恢复、meta/NBT 原地修改、数量变化不影响身份，以及缓存清理。安全和库存守恒回归仍通过。静态和计数证据见 performance-audit.json；纯服与 Pro 运行结果见各自 JSON，未运行图形客户端或客户端 Mixin 变换。

## 客户端实测清单

双端移除旧版并安装 0.11。优先检查本轮功能：

- AE 库存充足时空格+左键一次填满可用背包/快捷栏；松开空格仍按住鼠标不触发第二次，拖动不继续取物或弹配方。
- 物品栏、历史、书签和配方内分别操作；普通背包/终端格、无终端时保留原行为，不重复触发 NEI 原生配方/作弊取物。
- AE 仅有 58 件但有样板：仅取 58 件，不弹下单；真正零库存有样板：只弹下单；零库存无样板：明确反馈。
- 背包已有其他物品时保留原物品，补满目标未满堆叠；背包满且 AE 有库存时提示满包，不提取也不下单。
- 检查不可堆叠、16 件上限、同物品不同 meta/NBT；鼠标光标持有物、盔甲和额外槽位不被写入。
- 无电、越界、无 EXTRACT/CRAFT 权限、网络切换时不越权；重复点击限流不复制物品，Shift 取物与中键下单仍正常。

保留功能回归：分别在有线、无线终端下单：提交时不出现，实际完成后首格出现；完成第二种物品后前移；同种 meta/NBT 目标只占一格；九列终端第十种物品进入第二行；空位点击不取出其他物品；正常格点击、Shift 和右键取物仍正确。开启原生固定栏后检查位置、滚动、鼠标命中与窗口缩放；检查 Shift 暂停不会因空格崩溃。

关闭重开后已显示物品不再出现；保持终端打开满 60 秒后整栏消失，59 秒完成的新物品不延长期限；关闭期间完成的订单在下次打开同网络终端显示；不同网络、不同玩家不串栏。检查数量/确认/CPU 子页面返回时临时栏及原生下单均正常。

逻辑已检查，需用户实测。建议优先对比完成订单后首次打开、大网络搜索/排序、Shift 暂停、原生固定栏和 NEI 带复杂 NBT 图标的流畅度。真实 CPU 下单完成、合并订单归属、终端绘制/点击、网络延迟及模组共存尚未运行图形客户端验证。
